# Console API design — revision1, Control-owned

Additive extension of approved Draft HTTP/data model, ordinary same Boot ownership/session/CSRF/contracts. No role or business state architecture changes. Paths below use existing `/api/v1/catalog/admin/drafts` namespace and CATALOG_DRAFT_WRITE+owner/CATALOG_PUBLISH checks. Implement verifies exact DTO naming against canonical conventions and writes real canonical/resource OpenAPI alongside implementation, without breaking current operations.

1. Existing GET drafts: keep current limit/offset/default/has_more behavior; add optional `q` (title substring, trimmed, bounded250 chars, safe parameterized query), `category` TOP/BOTTOM/ONE_PIECE, `has_primary_image` true/false. Invalid/duplicate query fields fail canonical bounded error, not ignored arbitrary dynamic SQL. Add `total` for authorized filtered result count if consistent with repo envelope; existing required keys preserved. Stable order created_at DESC plus stable product UUID tie-break; no total beyond authorization scope. All query paths use latest immutable version snapshot, not any historical-version filter match.
2. GET `/summary`: real visible-draft total, counts with/without current primary image and by the three known categories; all counts effective authorized scope. No new ACTIVE/job metrics or hardcoded analytics. Return typed no-store bounded object and read-only transaction consistent enough for scoped counts; no query per row.
3. GET `/{productId}/versions`: bounded limit/offset/has_more read envelope for actual versions sorted version_no DESC, product/version IDs, version_no/status, title/category/created_at and image-presence summary only. No current-version impersonation or write side effects. GET `/{productId}/versions/{productVersionId}`: authorized actual historical title/description/category/version/status/time and public-safe image metadata (presence/media_type/byte_size/quality_state), no storage_uri/keys or secret metadata.
4. GET `/{productId}/versions/{productVersionId}/image`: returns that version's actual primary image bytes if present, matching product+version and same resource access; proper media type/size/no-store/nosniff and canonical not-found/errors. No URL redirect to S3 or public frozen image fallback. Read errors never mutate/repair image state.
5. GET `/{productId}/audit`: bounded pagination for allowlisted actual CATALOG_PRODUCT create/revise/primary-image events. DTO: event id/action/timestamp/product id/previous+new product-version IDs (or version numbers joined safely), optional validated trace_id and actor_id only if necessary for operational attribution. No user/account/session/library events, actor emails/usernames/credentials/storage paths/raw before/after JSON. Parent product ownership/admin authorization before rows; query filtering cannot bypass it. Immutable, no DELETE/PATCH audit endpoint.

Canonical error/status/no-store semantics from current contracts/source; CSRF for existing writes, no authorization weakening for new reads. Existing six Draft operations unchanged, public/internal APIs and9Swaggergroups preserved; new ops remain correctly documented within Catalog Drafts. No new dependencies/framework/event store. Existing schema should suffice; additive index/migration only if a measured query/invariant need warrants it, never edit old Flyway files.

All new field names/shape are recorded before tests at agreed HTTP/proxy/browser seams. Contract tests and live served-source parity are required. Confirm owner isolation across summary/list/version/audit/images using two Staff users and Administrator in the task DB. Supporting historical schema/docs are navigation, not permission to guess an unresolved role/publication policy.
